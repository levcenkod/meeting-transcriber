# ADR-001. Задачи живут в Trello, своей базы задач нет

Дата: 05.08.2026 · Статус: принято

## Контекст

Транскрайбер извлекает поручения из планёрок. Нужно решить, где они хранятся после того, как человек их принял.

В проекте нет базы данных вообще: результаты пишутся файлами в `output/`. Команда (Влад, Мария, Денис) уже живёт в Trello — задачи туда попадают руками через чат. Приложение работает локально на компьютере, постоянного сервера и доступа с телефона нет.

## Решение

Задачи хранит Trello. Транскрайбер создаёт карточку в одну сторону и забывает о ней. Своей базы задач, статусов и синхронизации нет.

Единственный след у нас — журнал отправки: одна строка на карточку с **первым сроком**, который никогда не переписывается.

## Последствия

- Не нужны СУБД, миграции, слой доступа, бэкапы — экономия 10–16 часов до первой пользы.
- Нет конфликта «кто хозяин даты»: у задачи один хозяин — Trello.
- Команда видит задачи там, где привыкла.
- **Ценой:** историю переносов Trello не хранит. Увидеть, что задача едет третий месяц, можно только сверив текущие дедлайны доски с журналом отправки — разово, по кнопке.
- Метрика исполнения по людям в реальном времени невозможна. Сознательный размен: партнёру не заказывают систему учёта его же просрочек.

Откатить трудно: как только карточки пошли на доску и там начали жить своей жизнью, перенос источника правды обратно к себе означает разбор двух рассинхронизированных списков.

## Что рассматривали и отбросили

- **Своя база задач в транскрайбере.** Отброшено: требует сервера и логинов, чтобы команда могла зайти, — это недели работы вместо вечера, и переезд людей с привычной доски.
- **Двусторонняя синхронизация с Trello.** Отброшено для v0: плюс 6–10 часов, требует ручной синхронизации по кнопке (публичного адреса под вебхуки нет), и появляется конфликт «кто нажал последним».
- **Карточка в Trello без дедлайна, срок только у нас.** Отброшено: противоречие спрятано, люди всё равно проставят свой срок на доске.
