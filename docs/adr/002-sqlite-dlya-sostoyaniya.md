# ADR-002. Состояние приложения — SQLite в named-томе; Postgres не берём

Дата: 06.08.2026 · Статус: принято · Дополняет ADR-001

## Контекст

ТЗ v0 (`docs/tz-v0.md`) требует хранить: метаданные встреч с настоящими датами, состояние приёмки (правки/принято/отклонено/отправлено), журнал отправки с неизменяемым первым сроком, маппинг спикеров на людей. ADR-001 запрещает **базу задач** — задачи живут в Trello. Владелец проекта разрешил Postgres, «если надо и есть смысл».

## Решение

**SQLite** (stdlib `sqlite3`, ноль новых зависимостей), файл в **named-томе Docker** (`app_data:/data`), не в bind-mount.

БД хранит только то, что не является задачей: `meeting` (метаданные + настоящая дата), `proposal` (предложения ИИ и их судьба в приёмке), `dispatch_journal` (первый срок, пишется один раз, UPDATE запрещён триггером), `speaker_map`. ADR-001 в силе: статусы, переносы и закрытие задач — в Trello, обратной синхронизации нет.

Бэкапы: `VACUUM INTO` в `/output/backups/` при старте и раз в сутки (попадает в bind-mount, т.е. виден на хосте); каждая строка журнала отправки дублируется сообщением в служебный Telegram-чат — журнал восстанавливается прокруткой чата.

## Почему не Postgres

- Нагрузка: один пользователь, ~40 встреч в квартал, сотни строк. Postgres — второй контейнер, healthcheck, отдельный том, обслуживание и миграции клиента ради нагрузки, которую SQLite не замечает.
- Зависимости: последние пять коммитов репозитория — борьба с пинами pip. `sqlite3` — стандартная библиотека, `psycopg` — новый участник этой борьбы.
- Бэкап/перенос: SQLite — один файл, копируется как файл. Дамп Postgres из контейнера на домашней машине — отдельная процедура, которую никто не будет делать.
- Слой доступа изолирован в `scripts/db.py`: если через год станет тесно — переезд на Postgres меняет один модуль, данные переливаются скриптом.

## Почему named volume, а не ./output

SQLite поверх Windows bind-mount под Docker Desktop (WSL2/9p) известен проблемами файловых блокировок и WAL. Named volume — линуксовая ФС, блокировки честные. Цена: файл БД не виден напрямую на хосте — это закрывается автобэкапом в `/output/backups/`.

## Сопутствующие решения (из того же разговора)

- **Бот просрочек**: standalone-скрипт (`scripts/overdue_bot.py`), которому нужны только API Trello и Telegram. Основной хостинг — GitHub Actions cron (секреты в Actions); локальный запуск — fallback. Причина: v0 сам констатирует «постоянного сервера нет», а выключенный комп делает молчание бота неотличимым от «просрочек нет».
- **Аудио**: исходник копируется в артефакты встречи (`{stem}_audio.{ext}`) до обработки и больше не теряется; отдача через endpoint с поддержкой HTTP Range (перемотка на таймкод). Причина: кнопка «послушать основание» — критерий приёмки ТЗ, а сейчас исходник уезжает в `processed/`.
